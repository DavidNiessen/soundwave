**[Play in your browser](https://soundwave.niessen.dev)** · **[Download the app](https://github.com/DavidNiessen/soundwave/releases/latest)** for Windows, macOS and Linux ![Soundwave in play: the note highway in front of the night-time stage, with the crowd, the lights and the score](docs/screenshot.webp) A rhythm game for your own music. Drop in a song (MP3, WAV, FLAC, OGG, M4A). The game analyzes its percussive, melodic and harmonic content and generates **Lead**, **Bass**, **Drums** and **Vocals** charts at four difficulties: | Difficulty | Lanes | Feel | | ---------- | ----- | ---------------------------------------- | | Easy | 4 | quarter notes, chord roots, no chords | | Medium | 4 | eighth notes, close two-note chords | | Hard | 4 | sixteenths, two-note chords | | Expert | 5 | literal transcription, three-note chords |

## Playing Default keys are `D F J K` (plus `L` on Expert), `Space` for overdrive and `Esc` (or `P`) to pause. All of them can be changed in Settings → Shortcuts. The pause menu also opens Settings (volume, audio offset and note speed take effect in the paused song; the rest from the next one) and asks before a song is restarted, skipped or left. Menus, controllers, audio output and replays are covered in the [playing guide](docs/playing.md). ## Documentation - [Playing](docs/playing.md): the game, menus, keyboard, controller and touch, audio output, replays and video export - [Track editor](docs/track-editor.md): changing any chart or writing one from nothing - [Playing together](docs/playing-together.md): parties, Showdown, leaderboards and Join from Discord on a self-hosted server - [Running a server](docs/server-setup.md): setting one up step by step ([server/README.md](server/README.md) is its reference) - [How analysis works](docs/analysis.md): stem separation, transcription, beats and bars, charting - [The 3D stage](docs/stage.md): how the stage, the band and the crowd are built and drawn - [Song files](docs/song-files.md): the `.soundwave` format and library backups - [Development](docs/development.md): the desktop app, the production web build and the tests - [The app icon](docs/app-icon.md): how the icon is rendered and cut - [Music and sound](docs/music-and-sound.md): the menu theme and interface sounds, and how to regenerate them ## Development You need [Node.js](https://nodejs.org/) 22 or newer and [pnpm](https://pnpm.io/) 10 or newer (CI uses pnpm 12). ```bash pnpm install pnpm dev # the game in the browser pnpm check # types, lint (oxlint), formatting (Prettier) and tests ``` Open http://localhost:5173 and add your own songs. [CONTRIBUTING.md](CONTRIBUTING.md) explains the checks, the code style and how to send a change. Building the desktop app, the production web build and the tests are in [docs/development.md](docs/development.md). ## Releases Every push to `main` is checked, and the desktop app is built for Windows, macOS and Linux and published as a **pre-release** (version: the next patch with the run number, such as `0.1.1-42`) for trying the newest work. Only the newest three are kept. Installed apps never update to a pre-release. A **full release** is started by hand: Actions › **Release** › Run workflow, choosing which part of the version to raise (or an exact version). It checks `main`, commits the version and tags it, builds and signs the app for all three systems, publishes the release with the updater's `latest.json`, and deploys the website to GitHub Pages. The website is only ever deployed from a full release. The desktop app looks for a new full release when it starts (Settings › Advanced › Updates; it can be switched off) and shows an **Update** button on the main menu when there is one. Installing downloads the release, checks its signature against the public key in `src-tauri/tauri.conf.json`, installs it and starts again. The matching private key is the repository secret `TAURI_SIGNING_PRIVATE_KEY`; without it a release cannot be built, and if it is lost, installed apps can no longer update themselves, so keep a copy somewhere safe. The workflows are in `.github/workflows`: `ci.yml` (checks, also on pull requests), `prerelease.yml` and `release.yml`. ## Contributing Issues and pull requests are welcome: see [CONTRIBUTING.md](CONTRIBUTING.md) and the [code of conduct](CODE_OF_CONDUCT.md).
